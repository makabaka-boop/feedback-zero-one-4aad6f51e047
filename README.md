# 后端交换作业：带键约束的存在规则 chase 推理后端

从零实现的 Python（仅标准库）后端：接收包含 `schema` / `facts` / `rules` /
`query` 的 JSON，在**所有合法世界共有**的语义下计算查询的必然答案
（certain answers）。规则结论支持单原子 `head` 与析取方案
`alternatives`（恰选一个）。

## 输入 / 输出契约

### 输入 JSON

```json
{
  "schema": {
    "Rel": {"arity": 2, "ranks": [0, 1], "key": [0]}
  },
  "facts": [{"rel": "Rel", "args": ["常量1", "常量2"]}],
  "rules": [
    {
      "body": [{"rel": "Rel", "args": ["x", "y"]}],
      "head": {"rel": "Out", "args": ["x", "z"]}
    }
  ],
  "query": {
    "body": [{"rel": "Out", "args": ["x", "z"]}],
    "project": ["x", "z"]
  },
  "closed_relations": ["Rel"]
}
```

* **schema**：按关系名声明
  * `arity`：正整数（整数禁布尔，`true/false` 一律拒绝）；
  * `ranks`：与 `arity` 等长的非负整数数组；
  * `key`：非空、无重复、取值在零基 `[0, arity)` 内的键列下标数组。
* **facts**：`rel` + `args`，参数为 Unicode 字符串常量，按集合解释
  （重复事实自动去重）。空事实数组合法。
* **rules**：非空 `body`，结论为 `head` / `alternatives` **恰选一个**
  （同时出现或同时缺失都整次拒绝），原子参数全部是变量（非空
  ASCII 字母数字串）。
  * `head`：单原子结论，每个 body 匹配都必须使其成立；
  * `alternatives`：非空方案数组，每项为非空原子数组（方案内原子
    须同时成立）；每个 body 绑定至少满足一个方案，允许多个同时
    成立，不同绑定相互独立；
  * 只在结论出现的变量是存在变量（存在某个对象，实现为匿名 Skolem
    对象）；方案内未在 body 出现的同名变量共享同一存在对象，跨
    方案、跨绑定各自独立，见证可经键合并与其他对象（含常量）相等；
  * **rank 安全**（对 head 或每个方案原子逐原子沿用）：结论共有
    变量所在列的 rank 不得低于该变量任一 body 位置的 rank；结论
    存在变量所在列的 rank 必须严格高于整个 body 所有位置的最高
    rank。
* **query**：非空 `body` 与非空 `project`，投影变量必须在 body 出现。
  可选 `aggregate`：省略时行为与旧版本完全一致；取值目前只支持字符串
  `"min_count"`，任何其他取值（含显式 `null`、非字符串）都定位到
  `$.query.aggregate` 整次拒绝。
* **closed_relations（可选）**：无重复关系名的数组，**允许空数组**；
  省略该字段时所有关系保持开放，旧输入完全兼容。每项必须是非空
  ASCII 字母数字串且引用已在 schema 声明的关系；非法项带零基下标
  路径（如 `closed_relations[0]`）整次拒绝。
* 关系引用与元数必须匹配；名称限非空 ASCII 字母数字串，常量为
  Unicode 字符串。

### 合法世界与不可满足

合法世界可以增加对象与事实（允许无限），但必须：包含全部输入事实、
满足全部规则、每个关系中键相同的元组在所有列上取值相同。对析取
规则，每个 body 绑定在合法世界中至少有一个方案成立；某个方案选择
导致键冲突时只排除该选择组合，**不**直接判整题无解——所有选择
组合都冲突时才不存在合法世界。不同字符串常量永不相等；未知对象
之间、未知对象与常量之间可以相等。

**封闭关系**（`closed_relations` 中声明的关系）在合法世界中的外延
必须**恰等于**输入 facts 中该关系去重后的元组集合，不能补造任何
记录；其余关系仍按上面的开放语义处理。规则向封闭关系推导出的每条
元组都必须能**整体**对应某条输入事实元组（常量列逐列相等，匿名列
绑定到对应事实列常量），禁止把不同事实行的列逐列拼接：

* 没有可对应的事实行 -> 该选择组合不可满足；
* 恰有一个候选 -> 匿名对象绑定常量，推导元组与事实行重合；
* 多个候选 -> 按候选分裂，与析取方案共用同一套分支枚举。

同一对象在全部位置取值一致：不同匹配对同一匿名对象的绑定经并查集
统一，要求它等于两个不同常量时该分支冲突；选择引发的新规则匹配与
键合并仍须满足全部声明。不存在任何合法世界时输出：

```json
{"status": "inconsistent"}
```

### 输出 JSON

* `{"status": "ok", "answers": [[...], ...]}`：只包含各分量都是
  **输入事实常量**的投影元组（匿名标识不能作为答案），去重后按
  **UTF-8 元组字典序**（逐分量比较 UTF-8 字节序列）排序。
* `{"status": "inconsistent"}`：无合法世界。
* 当 query 带 `"aggregate": "min_count"` 时，在上面的报告上**追加**
  字段 `min_count`：一个十进制非负整数字符串（如 `"0"`、`"1"`），
  原 `answers` 报告保持不变；无合法世界时仍只输出
  `{"status": "inconsistent"}`，不附带 `min_count`。

### min_count：身份未知时至少有多少条关联结果

科研目录审核里，待确认对象的**实际身份未知**：chase 为不同规则触发、
不同绑定各自造的匿名 Skolem 对象，在合法世界中允许是同一对象，也允许
等于某个输入常量。`min_count` 回答“在所有合法世界中，查询投影至少要
区分出多少个不同身份的关联结果”：

1. 对每个合法世界按 query body 求全部同态绑定，经 `project` 投影后
   按**实际身份**去重——匿名对象按并查集规范化后的代表身份计数，绑定
   到同一常量（或合并为同一等价类）的不同 Skolem 编号只算一个；
2. 取**所有合法世界**上该投影基数的最小值。

因此既**不能数 `answers`**（匿名结果被整体丢弃，题面例中 answers 为
空而 min_count 为 1），也**不能直接数 chase 的匿名编号**（不同编号允许
相等，直接数必然高估）。

身份识别不是任意的：每一次把两个自由空对象识别为同一对象、或识别为某
个常量，都可能引发**新的规则匹配、键合并、析取方案选择与封闭关系
见证**，这些后果必须全部自洽。实现上对每个存活 chase 分支枚举一步身份
识别，然后**把 chase 重新跑到不动点**（复用同一套分裂/收敛语义），丢弃
触发常量冲突或封闭关系无见证的识别方向；只在已经生成的结果上做合并是
错误的。存在见证可跨规则、跨绑定复用，也可等于输入常量；键约束可迫使
两个见证分离（分别钉到不同常量），析取产生的不同合法世界之间取最小。

* 空事实（无任何查询匹配）计数为字符串 `"0"`；
* 例：仅 `A(a)`、`A(b)`，`A`/`R` 的 rank 分别为 `[0]`/`[0,1]`、键均
  `[0]`，唯一规则 `A(x)→R(x,y)`，查询 `R(x,y)` 投影 `y`：两个见证可
  识别为同一对象，得 `min_count="1"`，而 `answers=[]`（见
  `examples/min_count_example.json`）。

## 语义与算法

### 为什么“只按现有事实连接”会漏答案

题面示例：规则 `A(x) -> R(x,y)` 会生成 `R(a, 匿名对象)`，规则
`B(x,z) -> R(x,z)` 生成 `R(a,b)`。`R` 以首列为键，两行键相同，因此
匿名对象必须等于常量 `b`，查询两列的必然答案就是 `(a,b)`。若只在
输入事实上做连接，第一条规则推出的信息就丢了。

### Chase（追赶）流程

1. 以输入事实初始化实例（常量用 `("c", s)`、匿名对象用 `("n", id)`
   内部表示）。
2. **规则触发**：求 body 的全部同态匹配；共有变量直接取值，存在变量
   取 Skolem 空对象。同一规则、同一共有变量取值只生成一组 Skolem
   对象（缓存），避免重复造对象。
3. **键约束合并**：键相同的两行在非键列取值不同时，用**并查集**强制
   等值——空对象之间合并、空对象绑定常量；若要求两个不同字符串常量
   相等，则当前分支不可满足。合并后重建索引，处理级联。
4. 重复 2–3 直到不动点。

### 析取 chase（alternatives）

单分支内先把确定性（`head`）规则与键合并追到不动点；随后取一个尚未
满足任何方案的 `(析取规则, body 绑定)`，按方案数**分裂子分支**，每个
子分支加入对应方案的原子（方案内存在变量取一组全新空对象，跨方案、
跨绑定各自独立）再各自收敛。收敛后仍无未满足绑定的分支即一个
**合法世界**（canonical model）。

* 导致常量冲突的分支被丢弃——方案冲突不等于整题无解；**全部**分支
  都冲突时才没有任何合法世界，输出 `inconsistent`；
* 每个存活分支都是合法世界，且任意合法世界都包含某个存活分支的同态
  像（沿该世界实际满足的方案逐次选择即得对应分支路径），因此
  **必然答案 = 各存活分支常量答案的交集**；
* 方案一旦满足便不会被撤销（键合并与新增元组只增不减匹配），每个
  `(规则, 绑定)` 至多分裂一次，分裂点总数有限，分支树有限。

### 封闭关系的 chase 处理

封闭关系在初始化时即由输入事实填满，推导只做**见证匹配**而不写入
新元组。一条推导元组进入封闭关系时，逐条比对该关系的输入事实行：
常量列必须逐列相等，匿名列在该候选行下要求等于对应事实列常量（同一
匿名对象在本行多列出现时必须指向同一常量）。无候选 -> 分支冲突；
唯一候选 -> 经并查集把匿名对象绑定到常量，后续规则匹配与键合并照常
级联；多候选 -> 记录挂起点并按候选事实行分裂子分支，与析取方案的
分裂共用同一个分支栈。因为见证按整条元组匹配，逐列拼接天然不可能
发生；不同候选对同一匿名对象要求不同常量时，由并查集的常量冲突
检查淘汰对应分支。

### 终止性（rank 归纳）

rank 安全条件保证：值只会出现在不低于其“诞生 rank”的位置，空对象
只能在严格高于 body 最高 rank 的位置诞生。按 rank 归纳，rank 0 只有
有限个输入常量；假设低于 rank r 的对象有限，则 rank r 处能诞生的
Skolem 对象由低 rank 的有限取值决定，也是有限的；键合并只会减少不同
对象数。因此每个分支的 chase 必然在有限步终止，得到有限的通用模型
（canonical model）；所有存活分支的常量投影交集，即所有合法世界
共有的必然答案。

### 查询求值

在每个存活分支的不动点模型上对 query body 做同态求值，保留每个投影
分量规范化后都是常量的元组；取**所有分支的交集**（即所有合法世界
共有的答案），去重并按 UTF-8 字节序排序。

### min_count 的搜索

`aggregate="min_count"` 不经过“常量答案交集”，而是直接数**实际身份**：

1. 在每个存活分支上对 query body 同态求值，投影分量经并查集规范化
   （常量 `("c",…)`、空对象代表 `("n",根)`），元组按身份去重得到该
   分支的投影基数；
2. 从分支的 canonical model 出发，枚举一步身份识别——任意两个自由
   空对象根合并，或某个自由空对象根绑定为实例中已有的常量；
3. 识别后克隆分支并**重新完整 chase**（`advance_branch` 的封闭见证
   分裂、析取方案分裂、键合并全部照常），触发常量冲突或封闭关系无
   见证的方向被丢弃；
4. 只继续探索投影基数严格下降的自洽延拓（身份只增粗、基数不反弹），
   并以与 Skolem 命名无关的结构签名记忆化；取全部可达不动点上的最小
   基数，跨所有初始存活分支再取最小。

识别只在既有对象之间进行、不引入新名字，rank 安全又保证每个 chase
分支有限，故搜索空间有限、必然终止。

## 使用方式

### 命令行（入口）

```bash
python -m chase_backend examples/spec_example.json /tmp/out.json
cat /tmp/out.json

# min_count 聚合：输出 {"status":"ok","answers":[],"min_count":"1"}
python -m chase_backend examples/min_count_example.json /tmp/mc.json
```

* 成功（含 `inconsistent` 这一正常结果）：退出码 0，输出文件被
  **原子替换**（先写同目录临时文件，`fsync` 后 `os.replace`）。
* 输入文件缺失、JSON 非法或字段校验失败：退出码非 0，错误以
  `{"error": ..., "path": "JSON路径"}` 打到 stderr，**不创建、不覆盖
  输出文件，旧结果完整保留**。

### Python API

```python
from chase_backend import solve
from chase_backend.errors import ValidationError

try:
    result = solve(payload)   # payload 为已 json.load 的 dict
except ValidationError as exc:
    exc.path     # 例如 "rules[0].head.args[1]"
    exc.message
```
